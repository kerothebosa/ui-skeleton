# Publication Upgrade Plan

This plan upgrades the repository into a public-ready npm package with a polished homepage README, GitHub Pages docs + demo, publish-safe automation, and community/repo hygiene.

## Phase 0 - Audit Baseline (completed)

### Findings
- `package.json` already has strong baseline metadata and an initial `exports` map.
- `dist/` is not present at rest (generated by build scripts).
- Internal docs source-of-truth exists in `docs/` with ordered index in `docs/README.md`.
- Playground exists with rich multi-route scenarios and shared config flows (`playground/`), currently served by a custom Node server.
- Existing workflows:
  - `.github/workflows/ci.yml`
  - `.github/workflows/publish.yml`

### Acceptance Criteria
- Baseline inventory captured in this plan.

### Stop Point / Commit Boundary
- Commit 1: `docs: add publication upgrade plan`

## Validation Matrix (run progressively and at the end)

- `npm ci`
- `npm run build`
- `npm run lint`
- `npm run typecheck`
- `npm run test`
- `npm run test:e2e`
- `npm run pack:check`
- `npm run demo:build`
- `npm run docs:build`
- Optional smoke:
  - `npm run demo:dev`
  - `npm run docs:dev`
  - install packed tarball in temp folder

## Risk Controls

- Keep `docs/` markdown as source-of-truth and reuse in site via includes.
- Keep demo behavior tied to built `dist` imports.
- Avoid adding secrets or local machine paths.
- Preserve existing testing behavior while extending automation.
